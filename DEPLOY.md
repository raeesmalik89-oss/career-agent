# Deploy Career Agent for free

This gets the app running on a public URL you can open in any browser, on a **free** plan,
with no credit card and no servers to manage. The easiest host is **Render**, which can read
the [`render.yaml`](render.yaml) blueprint in this repo and create everything in one step.

---

## Option A — Render Blueprint (recommended, ~5 minutes)

### 1. Get the code on GitHub
This repo already is: <https://github.com/raeesmalik89-oss/career-agent>. If you forked it,
use your fork's URL below.

### 2. Generate the one secret you need
The backend needs a `MASTER_KEY` (it encrypts stored tokens). It must be url-safe base64 of 32
bytes. Generate one and copy the output:

```powershell
python -c "import os,base64; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

(No Python? Any machine with Python works, or use an online "32 byte base64 key" generator.)

### 3. Create the Blueprint on Render
1. Sign up / log in at <https://dashboard.render.com> (the free "Hobby" account is enough).
2. Click **New +** → **Blueprint**.
3. Connect GitHub and pick the `career-agent` repo.
4. Render reads `render.yaml` and shows three resources it will create:
   - **career-agent-db** — free PostgreSQL
   - **career-agent-api** — the FastAPI backend
   - **career-agent-web** — the Next.js dashboard (this is the one you open)
5. It prompts for the one value marked *"sync: false"* — **MASTER_KEY**. Paste the key from step 2.
6. Click **Apply**. The first build takes a few minutes (it builds two Docker images).

### 4. Open it
When `career-agent-web` shows **Live**, click its URL (looks like
`https://career-agent-web.onrender.com`). You'll land on the login page.

### 5. Create your account
The app seeds no public login for you. Open a shell on the **career-agent-api** service
(Render dashboard → the service → **Shell**) and run:

```bash
python -m app.cli create-owner --email you@example.com --name "Your Name"
```

It prompts for a password. Then log in on the web URL. (Run `python -m app.cli --help`
in that shell to see every command.)

## What the blueprint wires up for you

| Setting | Value | Why |
|---|---|---|
| `DATABASE_URL` | from the free Postgres | the app reads it automatically; `postgres://` is normalized to the psycopg driver |
| `JWT_SECRET` | auto-generated by Render | signs login sessions |
| `MASTER_KEY` | **you paste it** | encrypts stored secrets; Render can't generate this exact shape |
| `COOKIE_SECURE` | `true` | Render serves HTTPS |
| `BACKEND_URL` | the API's internal address | the dashboard proxies `/api/*` to the backend server-side, so the browser sees one origin |

## Free-tier things to know

- **Services sleep after ~15 min idle.** The first request after that spins them back up and
  can take ~30–60 s. Normal for free plans.
- **A free Postgres database expires ~30 days after you create it.** Before then, either
  upgrade the database, or create a fresh free one and point `DATABASE_URL` at it.
- **No persistent disk on the free plan.** The database keeps your data; uploaded files
  (resumes/certificates) are stored on the container's temporary disk and reset on redeploy.
  Fine for a demo — move uploads to object storage for anything long-lived.

## If the dashboard can't reach the API

The dashboard bakes the backend address in at build time. If you see API/login errors:

1. Open **career-agent-web** → **Environment** and confirm `BACKEND_URL` is set
   (it should read as the API's `host:port`).
2. If it's missing or wrong, set it to the API service's internal address (Render shows it on
   the API service page), then **Manual Deploy → Clear build cache & deploy** so the new value
   is baked in.

## Option B — other free hosts

The app is just two Docker images plus a Postgres database, so it also runs on:

- **Railway** (<https://railway.app>) — deploy each Dockerfile as a service, add a Postgres
  plugin, and set the same environment variables. Railway gives a monthly trial credit rather
  than an always-free tier.
- **Fly.io** (<https://fly.io>) — `fly launch` in the repo root for the API and again in
  `frontend/` for the dashboard, plus `fly postgres create`. Set the same env vars with
  `fly secrets set`.

In every case the environment variables are the ones in the table above, and
`python -m app.cli create-owner ...` creates your first login.

## Run it locally instead

If you just want it on your own machine:

```powershell
# backend + frontend + Postgres, all on localhost
docker compose up -d --build
# then open http://localhost:3000
```

See the main [README.md](README.md) for local development without Docker.
